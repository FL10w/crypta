# Лабораторная №1: запуск и демонстрация

Реализация по ТЗ «2526 МАИ ОК 1.pdf»: C++23, собственные DES и DEAL,
семь режимов, четыре вида набивки, асинхронные операции с массивами и файлами.
Готовые криптографические реализации не входят в библиотеку или её сборку.

## Сборка и запуск

Лабораторная — самостоятельный проект. Её сборка и результаты находятся
в `Lab1/build`; следующие лабораторные можно собирать в собственных каталогах.

Нужны CMake ≥ 3.28, Ninja ≥ 1.11, GCC ≥ 15 и GoogleTest.
В текущей среде всё установлено. Python для сборки и запуска не нужен.

```bash
cd /home/flow/Documents/vsc/crypta/Lab1
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build -j 2
ctest --test-dir build --output-on-failure
./build/crypto
```

Для повторной демонстрации достаточно `./build/crypto`.
Для пересборки после правок — `cmake --build build -j 2`.
CMake самостоятельно отслеживает зависимости C++-модулей и пересобирает
только изменённые части. Цели `lib1`, `app1` и `tests1` — обычные цели CMake,
а не вызовы внешнего скрипта. Модуль `std` собирается отдельной библиотекой
из исходника установленного libstdc++.

Артефакты: `build/crypto` — демонстрация, `build/tests1` — тесты.
Параметр `-DBUILD_TESTING=OFF` позволяет собрать демонстрацию без GoogleTest.

Ожидаемый итог:

```text
100% tests passed, 0 tests failed out of 108
...
All 1036 roundtrips passed.
Skipped 84 file checks due to Zeros padding limitations.
```

Демонстрация перебирает DES, DEAL-128, DEAL-192, DEAL-256 ×
7 режимов × 4 padding. Для каждого сочетания проверяются три массива
(один байт, нулевой префикс, псевдослучайные данные; все заканчиваются
байтом `0x01`) и семь файлов:
текст, WAV, BMP, AVI, исходник тестов аллокатора на красно-чёрном дереве,
бинарный образец, пустой файл. Каждый результат сравнивается побайтно.
Для Zeros пустые файлы и файлы с нулевым последним байтом отмечаются
как `SKIP`; они проверяются с остальными набивками.

## Что показать на защите

1. Запусти `ctest --test-dir build --output-on-failure`.
2. Покажи DES с известным ответом и DEAL с независимыми ответами:

   ```bash
   ./build/tests1 --gtest_filter='DES.EncryptsKnownNistVector:DES.DecryptsKnownNistVector:Regression.DealMatchesIndependentCiphertextsForAllKeySizes'
   ```

3. Запусти `./build/crypto`. Для каждого сочетания выводится `[OK]`
   после сравнения всех образцов. При ошибке программа возвращает ненулевой код.
4. Покажи восстановленный текст и зашифрованные байты:

   ```bash
   cat build/demo/results/DES/CBC/PKCS7/5_text.txt.restored
   od -An -tx1 -N64 build/demo/results/DES/CBC/PKCS7/5_text.txt.encrypted
   cmp assets/video.avi build/demo/results/DEAL-256/CTR/PKCS7/6_video.avi.restored
   ```

   Успешный `cmp` ничего не выводит и возвращает код 0. Номера имён зависят
   от отсортированного набора входных файлов.

Свои файлы можно передать явно:

```bash
./build/crypto --file /путь/к/песне.mp3 --file /путь/к/фото.jpg --output /tmp/crypta-my-demo
```

Исходные файлы сохраняются; шифротексты имеют суффикс `.encrypted`,
восстановленные копии — `.restored`. Без аргументов программа находит
образцы относительно исполняемого файла, поэтому рабочий каталог не влияет
на запуск. `--assets DIR` задаёт каталог образцов; `--help` показывает параметры.
Ключи и IV генерируются заново при запуске и не сохраняются: это демонстрация
восстановления в одном запуске.

## Минутный аудиофайл: ручная проверка

Образец [assets/audio/music_60s.wav](assets/audio/music_60s.wav) — синтезированная
мелодия длительностью ровно **60 секунд**: 480 000 отсчётов, 8 000 Гц,
моно, PCM 16 бит. Размер файла — 960 044 байта. Последние 0,25 секунды —
тишина. Для точного восстановления этого файла используется PKCS7.

Минутный образец лежит в подкаталоге и запускается отдельной командой.
Обычная демонстрация без аргументов по-прежнему использует семь небольших
образцов непосредственно из `assets/`.

Быстрая проверка одного сочетания:

```bash
cd /home/flow/Documents/vsc/crypta/Lab1
cmake --build build -j 2
./build/crypto --file assets/audio/music_60s.wav --algorithm DES --mode CTR --padding PKCS7 --output build/audio-check
cmp assets/audio/music_60s.wav build/audio-check/DES/CTR/PKCS7/0_music_60s.wav.restored && echo "Файлы совпадают"
```

Ожидается `[FILE OK] DES CTR PKCS7 music_60s.wav`, время шифрования и
дешифрования в секундах, затем `All 4 roundtrips passed.` Четыре проверки —
это три массива и один минутный файл. Сообщение `Файлы совпадают` подтверждает,
что независимый `cmp` тоже не нашёл различий.

Для прослушивания открой `assets/audio/music_60s.wav` в плеере; он должен
показать длительность 1:00. Восстановленную копию также можно открыть в плеере,
предварительно сохранив её с расширением `.wav`:

```bash
cp build/audio-check/DES/CTR/PKCS7/0_music_60s.wav.restored build/audio-check/restored.wav
xdg-open build/audio-check/restored.wav
```

Проверка этого файла во всех семи режимах DES и всех вариантов DEAL
с набивкой PKCS7 (28 файловых циклов, выполняется дольше):

```bash
./build/crypto --file assets/audio/music_60s.wav --padding PKCS7 --output build/audio-verification
```

Ожидаемый итог — `All 112 roundtrips passed.` Это 28 сочетаний ×
(3 массива + 1 файл). Фильтры `--algorithm`, `--mode`, `--padding` позволяют
выбрать любое другое сочетание; без фильтра перебираются все его значения.
`--help` перечисляет допустимые значения.

Минутный файл ранее проверен во всех 28 сочетаниях алгоритма и режима
с PKCS7: восстановленные копии совпали с оригиналом по SHA-256. После
возврата обычной нулевой набивки `Zeros` для этого образца выводится `SKIP`,
поскольку он заканчивается нулевыми байтами. SHA-256 оригинала:
`fa465b61d64dc56a68fa165a2c10ff1c5189df8859453085f7c4dfcc70107421`.

## Соответствие пунктам ТЗ

| Пункт | Реализация |
| --- | --- |
| 1 | `PermuteBits`: оба порядка битов, индексация с 0 или 1. |
| 2.1–2.3 | `KeyExpansion`, `RoundTransformation`, `SymmetricCipher`. |
| 2.4 | `SymmetricCipherContext`, ECB/CBC/PCBC/CFB/OFB/CTR/RandomDelta, Zeros/ANSI X.923/PKCS7/ISO10126; одноимённые перегрузки для массивов и файлов, `std::async`. |
| 3 | `FeistelNetwork` с реализациями двух интерфейсов в конструкторе. |
| 4 | DES на сети Фейстеля, собственных расписании и функции раунда; использует `PermuteBits`. |
| 5 | Демонстрация DES на псевдослучайных данных и семи файловых образцах во всех сочетаниях. |
| 6 | DEAL-128/192: 6 раундов, DEAL-256: 8; `DEALRoundTransformation` адаптирует собственный DES к функции F. |
| 7 | Та же демонстрация для всех трёх вариантов DEAL. |

Параллельны ECB, дешифрование блоков CBC и PCBC, дешифрование CFB, CTR,
RandomDelta. Зависимые этапы CBC/PCBC/CFB при шифровании и генерация гаммы
OFB выполняются последовательно. На небольших данных используется один
поток; на больших число рабочих потоков ограничивается доступными ядрами.
Исключения рабочих потоков передаются вызывающему коду.

RandomDelta принимает необязательный дополнительный аргумент
`extra_parameters = {delta}`. `delta` — ненулевой массив размером в половину
блока. Если он отсутствует, берётся младшая половина IV. Состояние блока
равно `IV + i * delta` по модулю размера блока. Для остальных режимов
дополнительные параметры не определены и отклоняются.

## Нулевая набивка (Zeros)

Восстановлено поведение исходной лабораторной: данные дополняются нулями
до границы блока, а при дешифровании конечные нули удаляются. Контекст
передаёт исходные байты непосредственно алгоритму и не добавляет длину,
метки или другие служебные данные.

Для проверки точного восстановления с Zeros используются непустые данные,
заканчивающиеся байтом `0x01`. Исходные конечные нули невозможно отличить
от набивки, а пустой ввод в исходной реализации не поддерживается.
Такие файловые образцы демонстрация явно помечает как `[SKIP]` для Zeros,
не меняя их содержимое. Для ANSI X.923, PKCS7 и ISO10126 они проверяются
обычным образом. Для произвольного аудио или бинарного файла можно выбрать
`--padding PKCS7`.

Асинхронные операции удерживают реализацию контекста до завершения;
результирующий массив должен существовать до окончания операции.

## Проверка исправлений

После возврата обычной нулевой набивки выполняются 108 тестов. Проверки
включают 1316 сочетаний алгоритма, режима, padding и длины; 196 файловых
циклов; выживание операции после уничтожения контекста; обработку ошибок
рабочих потоков CFB; явный параметр delta; шесть независимых ответов DEAL.
В тестах Zeros используются непустые массивы и файлы с последним байтом
`0x01`. Отдельный тест проверяет, что контекст ECB/Zeros выдаёт обычный
шифротекст одного блока DES без добавленных служебных байтов.
Полная демонстрация на стандартных образцах выполняет 1036 успешных циклов
и явно пропускает 84 файловые проверки Zeros с неподходящими входами.

Происхождение ответов DEAL описано в [tests/DEAL_VECTORS.md](tests/DEAL_VECTORS.md).
Исходник образца аллокатора скопирован из
`FIIT_SP/allocator/allocator_red_black_tree/tests/allocator_red_black_tree_tests.cpp`;
он шифруется как файл и не участвует в сборке криптографических тестов.
Остальные образцы созданы локально для демонстрации.
